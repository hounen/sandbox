> 自分の業務をClaudeに落とし込み、「いつ・何をClaudeに頼むか」を決めるためのワークシート

---

## Step 1：自分の業務を書き出す

今週やった（やる）業務を思いつくまま書き出す。完璧に網羅しなくていい。

| 業務名 | 具体的な作業内容 | 1回あたりの時間 |
|--------|----------------|---------------|
| 例：バグ調査 | ログを読んで原因を特定する | 1〜2時間 |
| | | |
| | | |
| | | |

---

## Step 2：頻度で仕分ける

Step 1の業務を、発生頻度で3つに分類する。

| 頻度 | 定義 | 該当する業務（Step 1から転記） |
|------|------|-------------------------------|
| **毎日** | 毎日必ず発生する | |
| **定型** | 週数回・月数回だが手順が決まっている | |
| **週次実験** | 不定期・判断が伴う・まだ試したことがない | |

---

## Step 3：Claudeに落とし込めるか判定する

Step 2の業務を1つずつ、以下の3軸でチェックする。**◎が2つ以上 → 落とし込み候補**。

| 業務名 | 正解の有無 | 入力しやすさ | 出力の確認しやすさ | 判定 |
|--------|:--------:|:----------:|:----------------:|:---:|
| 例：テストコード作成 | ◎ | ◎ | ◎ | **◎** |
| 例：バグ調査 | △ | △ | △ | **△** |
| 例：顧客折衝 | ✕ | ✕ | ✕ | **✕** |
| | | | | |

> **判定基準**
> - 正解の有無：パターンがある・叩き台で十分なら◎
> - 入力しやすさ：テキスト・コードで渡せるなら◎
> - 出力の確認しやすさ：テスト実行や読めば判断できるなら◎

---

## Step 4：If-Thenルールに落とし込む

Step 3で◎・△がついた業務を、トリガーと行動のセットで書く。

### 毎日のIf-Thenルール

> 毎日発生する業務に組み込む。習慣化が目的。

| If（トリガー） | Then（Claudeへの行動） |
|--------------|----------------------|
| 例：エラーメッセージが出たら | エラー文＋該当コードを貼って原因と修正案を聞く |
| 例：実装タスクに着手するときは | Plan modeで実装方針を出させてから確認する |
| | |

### 定型業務のIf-Thenルール

> 手順が決まっている業務に組み込む。時短が目的。

| If（トリガー） | Then（Claudeへの行動） |
|--------------|----------------------|
| 例：テストコードを書くときは | 実装済み関数＋仕様を渡して正常系・異常系の叩き台を作らせる |
| 例：議事録を書くときは | メモ・録音テキストを渡して構造化させる |
| | |

### 週次実験のIf-Thenルール

> 週1回、新しい使い方を1つ試す。発見が目的。

| If（トリガー） | Then（試すこと） | 確認方法 |
|--------------|----------------|---------|
| 例：バグ調査をするときに1回 | ログをClaudeに渡して原因仮説を出させる | 自分の調査結果と照合する |
| 例：設計レビューの前に1回 | 設計書を渡して懸念点を列挙させる | レビューで指摘された内容と照合する |
| | | |

---

## 付録：落とし込んではいけないパターン

以下はClaudeに渡してはいけない・任せてはいけない。

- 顧客個人情報・社外秘資料・未公表の事業計画
- 最終的な設計判断・意思決定
- 顧客折衝・ステークホルダー調整
